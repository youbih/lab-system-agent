# 前后端分层与功能开发流程

本文结合实验室预约系统，以修改个人信息和修改密码为例，记录后端分层、前端开发流程以及一次功能操作如何连接前后端。

## 一、后端分层与请求流程

| 层 | 负责什么 | 以修改个人信息为例 |
|---|---|---|
| `schemas` | 定义请求、响应的数据结构和校验规则 | 允许修改哪些字段，字段是什么类型 |
| `api` | 定义接口路径、请求方法，接收参数并调用业务逻辑 | 接收 `PUT /api/user/me`，获取当前登录用户 |
| `services` | 实现具体的业务逻辑 | 更新用户字段，提交数据库修改 |
| `models` | 定义数据库表结构 | `users` 表有哪些列 |

一次请求在项目里的流转大致是：

```text
前端发送请求
    ↓
api 接收请求，FastAPI 按 schema 校验参数
    ↓
services 执行业务逻辑，通过 model 操作数据库
    ↓
api 返回结果，前端展示
```

以上是各层的分工，不是固定的编码顺序。如果需要新增数据库表或字段，还需要考虑 `models` 和数据库结构。并非每个接口都需要请求体 schema，例如获取当前用户信息时，可以通过 token 确认用户身份。

> 接口路径以当前代码为准：个人信息查询和修改已使用 `/api/user/me`，原笔记中的 `/api/user/update` 是较早的路径。

## 二、前端开发顺序

后端功能完成并验证后，可以按下面的顺序实现前端。顺序可以调整，但请求、页面、入口和路由需要配合。

1. 在 `src/api/user.js` 中封装请求，明确后端接口地址、请求方法和参数。
2. 创建 `src/views/Password.vue`，实现表单展示、数据绑定、输入校验和提交处理。
3. 在 `src/layouts/Layout.vue` 中增加“修改密码”菜单入口，处理点击事件。
4. 在 `src/router/index.js` 中注册页面路由，将页面地址对应到 `Password.vue`。
5. 联调验证：页面能打开、校验能触发、请求能发送、后端响应能显示、成功后能跳转；再验证旧密码无法登录而新密码可以登录。

| 文件 | 负责什么 |
|---|---|
| `src/api/user.js` | 封装向后端发送的请求 |
| `src/utils/request.js` | 封装 Axios，统一携带 token、处理响应和错误提示 |
| `src/views/Password.vue` | 显示修改密码表单，校验输入，提交修改 |
| `src/layouts/Layout.vue` | 提供菜单入口，点击后发起页面跳转 |
| `src/router/index.js` | 定义网址与页面组件的对应关系 |

## 三、前端 api 如何连接后端

前端的 `api` 文件封装 HTTP 请求，后端的 `api` 文件定义接收请求的接口。两者通过请求路径、请求方法、参数和响应格式配合。

```js
// src/api/user.js
import request from '@/utils/request'

export function updatePassword(data) {
  return request({
    url: '/api/user/password',
    method: 'put',
    data
  })
}
```

页面只需要调用 `updatePassword(data)`，不必每次重复编写 URL、请求方法和 token 处理逻辑。当前开发配置中，Vite 会把 `/api` 请求代理到 `http://127.0.0.1:8000`。

## 四、Password.vue 的主要代码作用

`Password.vue` 和 `Profile.vue` 都属于编辑表单，因此基本结构相似：

```text
展示表单 → 用户填写 → 校验输入 → 调用接口 → 处理结果
```

### 1. template：定义页面外观和交互绑定

`<template>` 中的卡片、表单、输入框和按钮决定用户看到的页面。

```vue
<el-input v-model="form.oldPassword" />
```

`v-model` 将输入框与 `form.oldPassword` 双向绑定：输入会更新数据，数据改变也会更新输入框。

```vue
<el-form ref="formRef" :model="form" :rules="rules">
```

这里的 `:model` 指向表单数据，`:rules` 指向校验规则，`ref="formRef"` 用于获取表单组件实例。

`el-form-item` 上的 `prop` 要与 `form`、`rules` 中对应的字段名一致，才能关联相应字段的校验。

### 2. script setup：定义数据与处理函数

| 代码 | 作用 |
|---|---|
| `import` | 导入页面要调用的 Vue API、接口函数和工具 |
| `form` | 保存原密码、新密码、确认密码 |
| `formRef` | 获取表单组件实例，用于调用校验方法 |
| `rules` | 定义必填等校验规则 |
| `validatePass` | 检查确认密码是否与新密码一致 |
| `submitting` | 控制保存按钮的加载状态 |
| `handleSubmit` | 校验表单、发送请求、处理成功后的操作 |

当前页面需要的导入：

```js
import { ref, reactive } from 'vue'
import { updatePassword } from '@/api/user'
import { ElMessage } from 'element-plus'
import { logout } from '@/utils/auth'
import router from '@/router'
```

表单数据和状态：

```js
const submitting = ref(false)
const formRef = ref()
const form = reactive({
  oldPassword: '',
  newPassword: '',
  confirmPassword: ''
})
```

`reactive` 用于保存响应式表单对象；`ref` 用于这里的布尔状态和组件引用。

### 3. handleSubmit：先校验，再提交

```js
const valid = await formRef.value.validate().catch(() => false)
if (!valid) return
```

这一步调用表单校验。如果校验失败，转换为 `false`，停止提交。

```js
const res = await updatePassword({
  old_password: form.oldPassword,
  new_password: form.newPassword
})
```

这里将前端字段 `oldPassword`、`newPassword` 转成后端要求的 `old_password`、`new_password`。

`confirmPassword` 用于前端检查两次新密码是否一致，不需要发送给当前后端接口。后端仍负责检查原密码正确、新旧密码不同，再对新密码做哈希并提交数据库修改。

当前前端没有“新旧密码不能一致”的单独校验，这个提示是在请求提交到后端后返回的；如果原密码本身不正确，后端会先返回“原密码错误”。

```js
if (res.code === 200) {
  ElMessage.success('修改密码成功')
  logout()
  await router.push('/login')
}
```

成功后提示用户，清除浏览器中保存的 token 和用户信息，然后跳转到登录页。这里清除的是当前浏览器的本地登录信息，不代表后端自动撤销了此前签发的所有 token。

`try ... finally` 中的 `finally` 会在成功或抛出异常后执行，用于恢复 `submitting.value = false`，结束按钮加载状态。

### 4. Profile.vue 与 Password.vue 的异同

| 对比项 | `Profile.vue` | `Password.vue` |
|---|---|---|
| 页面基础 | 卡片、表单、输入框、保存按钮 | 卡片、表单、输入框、保存按钮 |
| 打开页面时 | 在 `onMounted` 中请求已有用户信息，填入表单 | 显示空密码表单 |
| 特有操作 | 上传头像、使用 `computed` 显示角色名称 | 确认两次新密码一致 |
| 提交前 | 通过 `formRef` 校验表单 | 通过 `formRef` 校验表单 |
| 提交时 | 调用 `updateUserInfo` | 调用 `updatePassword` |
| 保存成功后 | 调用 `updateUser` 更新前端共享用户信息，留在当前页面 | 清除本地登录信息，跳转登录页 |

相似的是表单交互结构，不同的是业务字段、校验规则、接口和成功后的行为。

## 五、Layout.vue：提供页面入口

增加菜单项：

```vue
<el-dropdown-item command="password">修改密码</el-dropdown-item>
```

父组件需要监听事件：

```vue
<el-dropdown @command="handleCommand">
```

用户点击菜单项后，`handleCommand` 收到字符串 `'password'`，执行对应分支：

```js
} else if (command === 'password') {
  router.push('/manager/password')
}
```

`command` 是传给事件处理函数的值，它本身不会自动完成路由跳转；真正发起跳转的是 `router.push`。

## 六、router：让网址对应到页面

在 `/manager` 的 `children` 中配置：

```js
{
  path: 'password',
  name: 'Password',
  component: () => import('@/views/Password.vue')
}
```

| 配置 | 含义 |
|---|---|
| `path: 'password'` | 子路由路径，拼接父路径后得到 `/manager/password` |
| `name: 'Password'` | 路由名称，可以用于按名称跳转 |
| `component` | 匹配后加载的页面组件 |

文件名、路由名称和网址路径是不同的概念。页面文件名可以使用 `Password.vue`，网址仍使用小写的 `/manager/password`。Linux 文件名区分大小写，导入路径必须与实际文件名一致。

路由匹配后，页面显示在 `Layout.vue` 的以下位置：

```vue
<el-main>
  <router-view />
</el-main>
```

因此顶部栏和侧边栏保持显示，中间区域切换为修改密码表单。

## 七、完整操作流程

### 打开修改密码页面

```text
点击 Layout 中的“修改密码”菜单
    ↓
handleCommand 收到 'password'
    ↓
router.push('/manager/password')
    ↓
路由匹配 Password.vue
    ↓
在 Layout 的 router-view 中显示表单
```

### 提交修改密码请求

```text
用户填写表单，点击“保存修改”
    ↓
handleSubmit 校验前端表单
    ↓
调用 api/user.js 中的 updatePassword
    ↓
utils/request.js 携带 token 发送 PUT /api/user/password
    ↓
后端进行请求参数校验和身份验证
    ↓
services 校验原密码、新旧密码是否相同
    ↓
对新密码做哈希，通过 model 更新用户并提交数据库
    ↓
后端返回结果
    ↓
失败时显示错误；成功时提示、清除本地登录信息、跳转登录页
```

特别注意两个地址的区别：

| 地址 | 用途 |
|---|---|
| `/manager/password` | 前端页面地址，用于打开修改密码页面 |
| `/api/user/password` | 后端接口地址，用于提交修改密码请求 |

## 八、联调时的检查点

- 页面无法打开：检查 `Layout.vue` 的跳转地址与 router 的路径是否一致，例如避免将 `password` 拼成 `passwprd`。
- 改正路径后仍看到旧警告：先进入正确网址、清空控制台，再重新操作，确认是否产生新的警告。
- 点击提交报函数未定义：检查是否导入 `updatePassword`、`ElMessage`、`logout` 和 `router`。
- 后端接口返回 404：检查当前运行服务的 `/docs` 是否列出该接口，并确认服务加载了最新代码。
- 修改密码返回成功：再分别使用旧密码和新密码登录，验证旧密码失败、新密码成功。
